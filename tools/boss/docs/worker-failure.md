# Worker failure instead of deliberate parking

A worker must fix recoverable build, test, and merge failures and deliver validated work. An unrelated failure is not automatically a reason to stop: fix mechanical issues inline and describe that classification in the PR. Never publish known-red code or relax a repository check to manufacture a deliverable.

When a required credential, external dependency, or mandated approval genuinely prevents completion, report the exact cause with `boss propose blocked --reason "..."`, then end the attempt with `boss propose done --outcome blocked --summary "..."`. The summary must stand on its own. The first command alone is diagnostic, not a completed failure report. Do not leave a live worker waiting for a human.

For example, if a check can only be satisfied by adding an exclusion, the repository's approval requirement still applies. Do not add the exclusion. Record the failing command and the proposed policy decision, then fail the attempt. The coordinator can inspect the failure and decide whether an authorized retry is appropriate. This does not authorize workers to grant themselves exceptions.

The engine atomically marks the execution and latest run failed and writes `status = blocked`, `blocked_reason = worker_failed`, and the explanation into the task's `blocked_detail`. Both the declaration summary and companion blocker reason are included, along with the execution identifier. The existing task-show response and board blocked-detail surface expose that explanation. The failure is not described as a dispatch/startup failure.

Only after that transaction commits does teardown release the pane, worker slot, and cube lease. Automatic dispatch and orphan recovery do not mint replacements for this non-active task. This exclusion does not depend on attention delivery, `autostart`, or consuming the churn allowance. An explicit authorized restart can reuse the preserved workspace from a declared-blocked attempt. The nudge breaker uses the same failure transaction, as does an unverifiable delivery declaration without a resolvable PR.

## Compatibility and history

The original nudge-breaker park came from `aaa013b62256`: it left the worker in `waiting_human` with attention and stopped nudging. The shared idle-abandonment teardown originated in mono#1762 (`9c6db282d4ba`). The submit-time termination behavior came from mono#2934 (`f21f9bb62ef4`); mono#2958 (`4849c39c5004`) and mono#2963 (`ae7c7cfffa5e`) made deliberate parks durable against automatic recovery. This change edits those paths forward, retaining the nudge cap and resource release while replacing the park outcome. It does not revert mono#2964 or mono#2976, whose display improvements remain useful for historical rows.

Old engines wrote abandoned executions and left tasks active. The legacy admission and Backlog-display handling remains for those persisted rows so an upgrade cannot release a burst of replacement workers. New failed executions do not participate in that legacy park predicate. Historical workspace recovery also remains available. No feature flag enables the new failure behavior.

## Deployment

Rebuild and release the Boss engine (`//tools/boss/engine/core:engine`) through the normal Boss release/install flow, then restart the running engine on the released binary. Merging source alone does not update an already-running engine. Updated worker instructions are generated by that engine for subsequent runs; older workers' `done --outcome blocked` requests are compatible and receive the new failure semantics. The existing CLI and board already carry the task blocked-detail fields, so no new wire field or UI release is required for visibility.
