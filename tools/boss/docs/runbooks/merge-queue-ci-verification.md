# Merge-queue CI-fix verification

A green PR head does not establish that a merge-queue build passed. Boss captures the failing synthetic commit's checks, build URLs and job IDs for CI-fix revisions. GitHub timeline capture also records the first parent of that construction as `queue_base_sha` in each check snapshot; it can include earlier queued PRs. The brief distinguishes this historical base from current `origin/main`. If capture is incomplete, the worker must resolve the queue build and its base from commit statuses, check-runs and checkout logs.

Before a verdict, the worker fetches origin, rebases the PR onto current `main@origin`, resolves conflicts, and runs every failed target through Bazel on that combined tree. Whole-job failures require the complete build/test invocation from the job script. Isolated tests, filtered runs and checks on the old branch are insufficient. After fixes, rerun verification and `checkleft run`, and publish substantive changes or the changed rebase through Cube.

Both `boss propose done` and `boss engine ci mark-failed` accept `--queue-ci-evidence-file PATH`. The JSON object contains full `main_sha`, `verified_head_sha`, `queue_sha`, `queue_base_sha`, and a nonempty `runs` array. Each run records the exact captured `check_name` and `source_url`, complete Bazel `command`, zero `exit_code`, result `output`, and a `coverage` explanation naming all failed targets or the full job invocation. For a failing lint job, record `checkleft run` as its command. Multiple commands can cover one job. Every captured job must be represented. Evidence is worker-reported; the engine validates its structure, source coverage and captured queue/base identity, rather than rerunning commands in the RPC handler.

The declaration gate runs before stamping completion and survives a prior `mark-failed`. Missing, failing or incomplete evidence is rejected every time, leaving the worker live to finish verification. Rejected proposals never tear down the worker. Existing liveness/backstop handling remains responsible for a worker that cannot satisfy the gate; such a run fails visibly rather than being accepted as an infra/no-op verdict. A Trunk construction rejection with no captured failing build retains its existing conflict/batch-collision investigation path.

An unchanged verified head needs no artificial commit. For GitHub, the worker uses [enqueuePullRequest](https://docs.github.com/en/graphql/reference/pulls#enqueuepullrequest), with `expectedHeadOid` equal to the tested head, and records the returned `queue_entry_id` in the evidence. An already queued PR supplies its existing entry receipt. A rejected request is not a receipt. For Trunk, the existing poller resubmits when the verified revision reaches review and head checks are green; that path does not require a head change. Neither path retries until green or bypasses queue checks.

Verified requeue is declared `delivered`, even when no code changed. The unchanged-head delivery audit recognizes this evidence instead of demanding a cosmetic commit. A genuine external blocker after successful verification can be declared `blocked` with the same evidence; its summary must name the main commit, commands and results. Do not hand recovery back as coordinator resubmission without that verification.

`boss engine ci classify` requires the same evidence file before accepting a queue verdict. For a changed head whose checks are pending, the worker can arm GitHub auto-merge with the tested SHA as `--match-head-commit`, then finish without waiting for CI. The queue-entry receipt requirement applies to unchanged-head delivery. The existing merge mechanism and all queue checks still apply.

This flow takes effect when the updated engine and worker CLI are deployed; it has no new feature flag. The existing run-done proposal seam still controls synchronous completion.
