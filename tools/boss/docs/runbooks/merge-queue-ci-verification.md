# Merge-queue CI-fix verification

A green PR head does not establish that a merge-queue build passed. Boss captures the failing synthetic commit's checks, build URLs and job IDs for CI-fix revisions. GitHub timeline capture also records the first parent of that construction in the attempt-level `queue_base_sha` column, including when no checks were captured; it can include earlier queued PRs. The brief distinguishes this historical base from current `origin/main`. If capture is incomplete, the worker must resolve the queue build and its base from commit statuses, check-runs and checkout logs.

Before a verdict, the worker fetches origin, rebases the PR onto current `main@origin`, resolves conflicts, and runs every failed target through Bazel on that combined tree. Whole-job failures require the complete build/test invocation from the job script. Isolated tests, filtered runs and checks on the old branch are insufficient. After fixes, rerun verification and `checkleft run`, and publish substantive changes or the changed rebase through Cube.

Both `boss propose done` and `boss engine ci mark-failed` accept `--queue-ci-evidence-file PATH`. The JSON object contains full `main_sha`, `verified_head_sha`, `queue_sha`, `queue_base_sha`, and a nonempty `runs` array. Each run records the exact captured `check_name` and `source_url` (or a resolved HTTPS build URL when the captured URL is empty), complete Bazel `command`, zero `exit_code`, result `output`, and a `coverage` explanation naming all failed targets or the full job invocation. For a failing lint job, record `checkleft run` as its command. Multiple commands can cover one job. Every captured job must be represented, and non-lint jobs require a `bazel test` run; lint-only or build-only evidence cannot stand in for a failed test job. Evidence is worker-reported; the engine validates its structure, source coverage and captured queue/base identity, rather than rerunning commands in the RPC handler.

The declaration gate runs before stamping completion and survives a prior `mark-failed`. Missing, failing or incomplete evidence is rejected every time, leaving the worker live to finish verification. Rejected proposals never tear down the worker. Existing liveness/backstop handling remains responsible for a worker that cannot satisfy the gate; such a run fails visibly rather than being accepted as an infra/no-op verdict. A Trunk construction rejection with an explicitly empty check list retains its existing conflict/batch-collision investigation path; malformed captures use the verification brief and require resolving the missing provenance.

An unchanged verified head needs no artificial commit. For GitHub, the worker uses [enqueuePullRequest](https://docs.github.com/en/graphql/reference/pulls#enqueuepullrequest), with `expectedHeadOid` equal to the tested head, and records the returned `queue_entry_id` and `queue_entry_enqueued_at` (`mergeQueueEntry { id enqueuedAt }`) in the evidence. After the declaration the engine checks the receipt against GitHub (the PR must be queued under that entry at the verified head) and files a flagged attention, re-arming the blocked signal, on a mismatch; it also confirms the verified head is the PR head and contains `main_sha`. The `enqueuedAt` time becomes the dedup boundary: queue failures at or before it are superseded by the requeue. An already queued PR supplies its existing entry receipt. A rejected request is not a receipt. For Trunk, the existing poller resubmits when the verified revision reaches review and head checks are green; that path does not require a head change. Whole-job verification uses `bazel test`, `checkleft run` for lint jobs, or the job's own npm/pnpm/yarn command for non-Bazel jobs; a Trunk capture names each failed job `Trunk merge queue: <pipeline>/<job label>` so the lint/test split is decided per job. Neither path retries until green or bypasses queue checks.

Verified requeue is declared `delivered`, even when no code changed. The unchanged-head delivery audit recognizes this evidence instead of demanding a cosmetic commit. Accepting a queue receipt atomically retires the failed attempt and clears its failure signal; the applied proposal retains the receipt. The archived episode remains deduplicated by queue SHA, while a later failed construction at the same PR head can consume the next normal budget slot. A genuine external blocker after successful verification can be declared `blocked` with the same evidence; its summary must name the main commit, commands and results. Do not hand recovery back as coordinator resubmission without that verification.

`boss engine ci classify` requires the same evidence file for `flaky_or_infra` and `unfixable` verdicts; `tractable` can be recorded as metadata before verification. Failure reasons contain a compact SHA/command/exit-code summary rather than full run output. For a changed head whose checks are pending, the worker can arm GitHub auto-merge with the tested SHA as `--match-head-commit`, then finish without waiting for CI. The queue-entry receipt requirement applies to unchanged-head delivery. The existing merge mechanism and all queue checks still apply.

This flow takes effect when the updated engine and worker CLI are deployed; it has no new feature flag. The existing run-done proposal seam still controls synchronous completion.
