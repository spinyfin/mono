Writes still go through `PUT /api/v3/user/tracked-fencers/{fencerId}/british-fencing-membership` (caller must track the fencer). `GET /api/v2/user/me` hydrates `trackedFencers[].britishFencingLicence` from the sidecar in a single batched query (`cosmos::id_in` over the tracked fencer ids) so the settings editor does not need a new read; a failure to load the sidecar degrades that field to unset rather than failing the whole `/user/me` response. That field is no longer a stored per-user assertion: the write path does not patch the user document, the generic `PATCH /api/v2/user/me` json-patch endpoint unconditionally rejects any path containing `britishFencingLicence`, and a one-shot migration strips leftover keys.

Standings / composition / history still require a **tracking viewing context** (signed-in caller who tracks the fencer, or a live results-share link whose owner tracks the bound fencer). A signed-out visitor with no share token still sees no British chips. Share links are not widened beyond that owner-scoped grant.

Capture no longer has a multi-asserter ambiguity path. One shared record cannot produce two values, so `resolve_british_licence` / `BritishLicenceResolution::Ambiguous` / `CaptureCounts.britishLicenceAmbiguous` are gone.

### Migration

Via admin task `migrate_british_fencing_licences` only — it is not run automatically on backend startup, since it does a full uncached scan of the users container and every replica would otherwise pay that cost on every process start:

- Exactly one distinct per-user licence for a fencer → adopt it (`setBy` = lexicographically-smallest asserting user id).
- Two or more distinct licences → leave the shared record unset, log a warning with **fencer id and distinct-count only** (never the membership ids), and leave that fencer's per-user `britishFencingLicence` values in place on the user documents so the competing assertions stay recoverable until a human reconciles them.
- A fencer that already has a sidecar record is not overwritten.
- Then strip `britishFencingLicence` from user documents that still carry it, except for fencers left in conflict above.
