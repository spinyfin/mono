### PR description

## Summary

When the coordinator session restarts (Claude Code update, app/engine restart, crash, or the restart ceiling firing), the incoming session starts with zero knowledge of what was said to the outgoing one in chat. This adds a **coordinator session handoff**: the outgoing session keeps a short rolling brief current via `boss handoff write`, and the engine hands it to every fresh coordinator session as that session's first prompt. The motivating incident (a chore filed against a CI host that had already been reported as shut down in chat, then an agent briefed on tmux state that had already been reversed) is the failure this closes.

It extends the existing restart-time coordinator lifecycle in `coordinator_tmux.rs` rather than adding a parallel injection mechanism. The existing prompt-change nudge only fires on the *adoption* path (engine restarted, coordinator survived). The handoff case is the other path — `start_new`, a fresh `claude` process with no context — and that is where the brief lands. The two are complementary: an adopted session keeps its context and gets no brief; a fresh one gets the brief and no nudge.

## Design decisions

**1. What triggers the write: a rolling handoff, never shutdown-only.** Every event on the list kills the session with no chance to run anything, so a shutdown hook would silently produce nothing in exactly the case that matters. Instead the coordinator prompt (`bossSystemPrompt` in `BossPaneModel.swift`, new "Session handoff" section) binds the session to rewrite the whole handoff in the same turn whenever a fact that changes the world, a decision, or a prohibition is stated in chat; when an open thread starts or resolves; and before acknowledging any restart/update/reset request. An abrupt kill therefore cannot yield an *empty* handoff with no indication: the engine stamps every write with the writer session's spawn token and records each session's start time, so the brief can say "the session that just ended never wrote one; the newest handoff is from an earlier session, 3 days ago" (**STALE**) as opposed to "written by the session that just ended, 4 minutes ago" (**PRESENT**). A handoff written while no coordinator session was on record (empty writer token) is reported as "writer unknown" rather than folded into either of those, since the engine genuinely cannot say who wrote it.

**2. Where it lives:** one JSON value in the engine's `metadata` table (`coordinator.handoff`: body, `written_at`, `writer_spawn_token`). Coordinator-private, engine-owned, never in a repo, reachable only through `boss handoff …`. The coordinator record additionally stamps `coordinator.tmux_spawned_at`.

**3. How the incoming session consumes it: injected at start.** `start_new` composes a session-start brief, writes it to `.claude/handoff-brief.txt` in the coordinator session directory, and launches `claude … --permission-mode auto "$(cat '<brief>')"` — the same positional-initial-prompt shape worker panes already use. The session reads it on its first turn before anyone types anything; no pane injection to time, no reliance on the model choosing to open a file. The brief carries absolute UTC timestamps and elapsed ages for both the handoff and the previous session's start, plus why the previous session ended (`CoordinatorStartReason`: first creation, tmux session missing, `claude` exited, reset, model change). Missing and unreadable are distinct states (`HandoffState`); neither is ever passed off as "nothing to hand off" — a first-ever session gets a non-alarming "none is expected", every other missing case gets "NO HANDOFF AVAILABLE … this is NOT the same as nothing to hand off", and a corrupt stored value gets "HANDOFF UNREADABLE" with the decode error. If the brief file itself cannot be written, the launch falls back to a short inline notice naming the error and pointing at `boss handoff show`, never a bare session. Every launch is audited (`coordinator_handoff_brief`), as is every write (`coordinator_handoff_written`). `boss handoff show` re-reads the stored handoff at any time (after compaction, say) and returns an error, not an empty result, for the unreadable case, rendering age via the engine's shared `format_elapsed_ago` and the written-at timestamp via the CLI's local-time convention. Consumption is not optional-by-default: it is the first prompt of the session.

**4. What goes in it:** facts stated in chat with the time they were stated, decisions, open threads with ids, and explicit prohibitions. Not a transcript, not engine-readable status, not memory-store content. The engine enforces a 16 KiB cap and rejects blank bodies. The prompt gives a heredoc template so the coordinator needs no scratch file or Write tool.

**Transcript fallback.** When `~/.claude/projects/<encoded session dir>/` exists, the brief names it as a slow last resort only. It is not the mechanism.
