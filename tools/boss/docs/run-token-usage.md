# Per-run token usage

Hook ingress calls `engine/app/src/app/transcript_persist.rs::persist_transcript_and_capture_cost`, which tails the raw provider transcript through `engine/core/src/run_cost.rs::RunCostCapture::capture_and_persist`. `engine/work-db/src/run_rows.rs::set_run_cost_snapshot` assigns the cumulative observation to the execution's agent-session `work_runs` row. Repeated hooks and replay after restart do not increment the stored totals. Completion is not required to retain usage: interrupted and orphaned runs keep their observed tokens too.

## Coverage

| Driver              | Before native usage capture                               | Authoritative source and current mapping                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Claude Code         | Captured input, cache creation, cache read, output, model | `run_cost.rs::ingest_assistant`: `message.usage` on assistant rows, replacing by `message.id`; model from `message.model`. Cache creation also retains the reported five-minute/one-hour split.                                                                                                                                                                                                                                                                                                                                                              |
| Codex               | Captured input, cache creation, cache read, output, model | `run_cost.rs::ingest_codex_event`: latest `event_msg/token_count` cumulative `total_token_usage` per transcript; `input_tokens`, `cache_write_input_tokens`, `cached_input_tokens`, `output_tokens`; model from `turn_context.payload.model`. Existing Codex capture preserves its input field as reported and defaults missing usage categories to zero; this change does not reinterpret that historical convention.                                                                                                                                       |
| Grok                | No token capture; raw ACP rows were ignored               | `run_cost/native.rs::grok`: `params.update.usage` on `turn_completed`, keyed by transcript and `prompt_id`. Fresh input is `inputTokens - cachedReadTokens`; cache read is `cachedReadTokens`; output is `outputTokens`, already including `reasoningTokens`. Model comes from the sole key in `modelUsage`. Both cancelled and successful turns count. `agent_active_ms` is left unknown: ACP `apiDurationMs` is model API latency only, and turn wall time (`turn_started`/`turn_ended` in `events.jsonl`) is not on the transcript the cost tailer reads. |
| Antigravity (`agy`) | No token capture; raw planner rows were ignored           | `run_cost/native.rs::NativeUsage::ingest`: `PLANNER_RESPONSE` rows keyed by transcript and `step_index`. `input_tokens` is fresh input, `cache_read_tokens` and `output_tokens` map directly, and `model` is retained. Older captures without token fields remain unmeasured.                                                                                                                                                                                                                                                                                |

Neither captured Grok nor Antigravity dialect reports cache creation or its TTL split. Those columns are NULL, not zero. Grok `agent_active_ms` is also NULL: `apiDurationMs` is API latency, not the whole-turn duration Claude and Codex record, and the cost tailer does not read `events.jsonl` `turn_started`/`turn_ended`. Missing, malformed, negative, or inconsistent counts remain unknown. If any response omits a category, the cumulative category remains NULL instead of presenting a partial sum as the complete measurement. Different observed models within one run leave the run model unknown rather than pricing all tokens as the last model.

Every newly created run starts with a `usage_unavailable` reason of `No provider token usage observed`, including runs whose transcript never arrives. A valid usage observation clears it. Native responses missing input, output, or cache reads replace it with an explicit incomplete-response reason. The migration labels historical unmeasured rows too; it does not invent or backfill tokens.

## Evidence and reports

`run_cost/testdata/grok_turns.jsonl` contains the two verbatim `turn_completed` rows from `investigations/ghostty-grok-pane-viability-artifacts/ghosttykit_host/evidence/esc_interrupt/session_telemetry_excerpt.md`. The headless CLI JSON in that investigation reports fresh `input_tokens` separately, whereas ACP's `inputTokens` includes cache reads. The parser deliberately handles the interactive transcript dialect. It does not read `_meta.totalTokens` from text chunks or estimate counts from text.

`run_cost/testdata/agy_planner.jsonl` copies `engine/driver/src/agy/testdata/tool_calls_1.5.9.jsonl`. Its three planner rows report 20,570 fresh input, 8,101 cache reads, and 109 output tokens. The Grok fixture reports 2,486 fresh input, 24,576 cache reads, and 115 output tokens. Fixtures require neither provider credentials nor a live CLI.

`boss cost window` includes a `by_driver` breakdown from the execution's recorded launch driver, not its current work-item preference. Unknown category totals serialize as null and print as `unknown`. `tokens_partial` is true only when a measured run lacks a category, so an unmeasured run in a bucket does not hide complete Claude or Codex category sums. A bucket with no measured runs leaves every category unknown rather than reporting zero. `usage_unavailable` lists recorded reasons. Run counts distinguish absent usage from observed zero. Task and top reports retain the same unknown-category semantics. Known tokens on a partially measured run still rank in `boss cost top`.

Grok and Antigravity report tokens only: no verified subscription/CLI rates are assumed, even when Antigravity names a model family present in the API pricing table. `--usd` leaves their estimated cost absent and lists the model in `pricing_gaps`. Other drivers with incomplete categories are likewise excluded from dollar estimates. The optional estimate remains separate from measured tokens.

`boss cost rows` (`GetTokenUsageRows`) returns the same figures at run grain as a task → execution → run tree, built by `engine/usage-report` over `engine/work-db/src/cost_report_db.rs::usage_records_for_window`. Each run carries its per-class tokens (a class the provider did not report is NULL, never zero), a coverage state (`measured`, `partial`, `zero`, `unmeasured`), its input convention (`net` for Claude, Grok and Antigravity; `gross` for Codex), its recorded `usage_unavailable` reason and a list of caveat codes. List totals sum each run once (direct); a chain root also carries an inclusive total over its revisions. Executions that have no task row (answer agent, review guide, automation triage) are included. `--usd` prices only measured runs with net input, every class reported and a model in the rate table; Grok and Antigravity are excluded by driver (`subscription_unpriced`) and Codex by its gross input (`capture_unnormalised`). The design is `docs/designs/token-usage-window.md`; `engine/usage-report/fixtures/token-usage-seed.sql` seeds an isolated engine with every case.
