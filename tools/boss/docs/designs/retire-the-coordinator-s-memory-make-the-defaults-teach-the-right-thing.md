## TL;DR

Three-fifths of the Boss coordinator's private memory store (61 of the 102 classified notes) was an unfiled bug report: workarounds for defaults that make the wrong thing easy, and manual procedures that exist only because Boss lacked a verb or a view. This project converted those notes into dependency-ordered implementation work that **fixed the defaults and built the missing surfaces**, so the knowledge lives in the product instead of a notebook that dies with each session. It also encoded a **retention policy** in the coordinator prompt: memory is for the operator's personal working style and facts about the operator only; anything describing Boss's own behaviour is a defect that must become a work item, not a note.

**What shipped in the implementation wave:** the high-leverage diagnostic (`bossctl dispatch diagnose` signature matching, not a parallel `doctor` verb), honest `agents list` (pool + exec kind + stale-activity downgrade + SessionStart-authoritative model), unified work-item list/show, capacity-surface vocabulary cleanup, first-class effort provenance + `blocked_detail` tooltip + `boss <kind> comment`, product decision records (engine + CLI, not a new work-item status), stranded-runbook migration (mono wave complete at first postmortem; flunge PR still open), read-only CLI verbs, GitHub importer escape hatch, coordinator prompt surgery (CLI-defect deletion + Category-C rules + D4 retention), and a partial A14 CLI batch.

**What shipped after the first postmortem (incremental, 2026-07-27):** more stranded coordinator-memory knowledge landed as mono docs ([#2445](https://github.com/spinyfin/mono/pull/2445): Bazel/Xcode LaunchServices pin, forensic surfaces, work-item id text-leakage rule + operational-docs index in root `AGENTS.md`); one additional Category-C judgement rule in the coordinator prompt ([#2444](https://github.com/spinyfin/mono/pull/2444): a merged origin PR does not moot a review-findings followup).

**What did not ship with the code wave (project acceptance still open):** the operator-approved memory **pruning pass** (T-prune) that actually deletes the retired A/B notes; three flunge runbooks still live only on open PR `brianduff/flunge#1148`; the deferred app-side pool/kind Agents-tab render (B6); and most of the long A14 grab-bag beyond the four items materialised as one task. See [Residual / uncompleted](#residual--uncompleted).

## Goals

- Convert all 61 Category-A (code default / product defect) and Category-B (missing surface) memories into PR-sized, dependency-ordered implementation items, each naming the specific memory files it retires so completion is _measurable_, not asserted. _(Code/surfaces largely shipped; **measurable memory retirement still requires T-prune**.)_
- Fix the defaults so the wrong thing becomes hard to do, rather than documenting the workaround. Every item is scored against the operator's organising question: _"is that actually a prompt thing, or a defaults thing?"_ — a rule asking the coordinator to remember not to trip over a default is a defect in the default. _(Held.)_
- Build the missing read/diagnostic surfaces (`bossctl` diagnose signatures, honest `agents list`, structured fields, read-only CLI verbs) that today only exist as hand-written decision trees in private memory. _(Shipped; verb name is `dispatch diagnose`, not `doctor`.)_
- Cut the coordinator prompt down to the judgement rules code genuinely cannot encode, and remove the ~90 lines that restate CLI shapes the CLI itself knows. _(Shipped in two PRs: deletion then Category-C / D4 add.)_
- Establish a **durable knowledge home and a retention/curation policy** so operational runbooks reach workers (repo `AGENTS.md`/`docs/`) and the memory store does not silently rebuild into a second bug tracker. _(Policy in prompt shipped; mono runbooks expanded again in #2445; flunge half of B3 still open; prune not yet run.)_

## Non-goals

- **Not an implementation of this postmortem.** The original design run delivered the design doc only; the implementation wave that followed is what this revision describes. This postmortem revises the doc only.
- **No "banned phrases" or "known caveats" prompt section.** Held — surfaces were fixed instead.
- **No duplication of the worker proposal API** (worker proposal + taxonomy read-access design). A11 points at it; D2 remains a dependency note, not a built path.
- **No Boss-internal mirror of design docs or PR artifacts.** GitHub is source of truth; Boss stores `(repo, path, ref)` only. Held.
- **No further nudge-loop circuit breaker (A6) or doc-link point-patch (A8).** Both were already fixed pre-wave; only live-verify + memory retire remained (still open as part of T-prune).
- **Do not touch the slot model.** Held. Slot-adjacent fixes stayed tactical (SlotBusy wording; no slot_id echo).
- **Nothing that reclaims workspaces faster, caps workspace count, or adds a shared bazel cache.** Held.
- **Do not automate memory deletion.** Held — T-prune still presents a list for operator approval; deletion stays a human act.

## The finding (background)

A full read of the store classified every note. The table below is the classification at design time (2026-07-24), reconciled against the 107 files the store then held:

| Category                                  |   Count | Meaning                                                                                               |
| ----------------------------------------- | ------: | ----------------------------------------------------------------------------------------------------- |
| A — code default / product defect         |      40 | Memory exists because a default or surface makes the wrong thing easy. Fix the code; the memory dies. |
| B — missing tool / missing surface        |      21 | Memory encodes a manual procedure that exists only because Boss lacks a verb, view, or log.           |
| C — genuine behavioural contract          |      23 | Judgement rules no default can enforce. Prompt content.                                               |
| D — personal recall / operator preference |      18 | Legitimately private. Stays as memory.                                                                |
| E — stale / redundant / wrong             |       0 | Already in the prompt, superseded, or a fixed bug. The whole category has been deleted.               |
| **Total classified**                      | **102** |                                                                                                       |

The store held **107** files at design time. 102 carried a classification above; the residual five were written after the sweep and are unclassified — the first job of T-prune is still to classify them. Category E was empty because every note in it had already been deleted, along with six Category-A notes whose defects were verified fixed (A7 ×2, A9, A12, A13 ×2) and one Category-C note whose contradiction the operator resolved by deletion.

This project covers **A and B — all 61 items.** C informed the prompt-surgery item; D stays where it is.

The organising principle, verbatim from the operator when the coordinator proposed encoding an operating rule into the system prompt:

> "is that actually a prompt thing? It feels like a 'cube should have longer leases by default' thing."

Every item below is scored against that question.

## Alternatives considered

### Alternative 1 — Keep the memory, improve the prompt (status quo, scaled up)

Leave the defaults alone; move the highest-value memories into the coordinator system prompt and write better caveats. **Rejected.** This is precisely what the store already was, and it had a measured failure record. Prose in the prompt does not reach workers, grows without bound, and dies with the session's context.

### Alternative 2 — Generate the mechanical prompt sections from the CLI schema

Generate mechanical CLI-shape sections from clap so they cannot drift. **Partially adopted, deferred (D1).** v1 deleted the lines made obsolete by surface fixes instead. After surgery, residual mechanical content was small enough that schema-generation remains `future / not a v1 blocker`.

### Alternative 3 — Chosen and executed: fix the defaults, build the missing surfaces, then shrink the prompt and set a retention policy

Treat each Category-A/B memory as a defect ticket against a default or a missing surface. That is what the implementation wave did.

## Chosen approach (as planned and as executed)

Four movements, heavily parallelised inside phases:

1. **Highest-leverage surfaces and vocabulary (Phase 1).** Diagnostic signatures (B1), honest `agents list` (A3), unified lookup (A4), delete "pool" vocabulary (A5), lease TTL (A1 residual).
2. **Structured fields, then prompt surgery (Phase 2).** Effort provenance, blocked-detail tooltip, comment verb (A10); prompt surgery; decision records (B2); runbook migration (B3); read-only verbs (B4); then operator-approved prune (T-prune — **not yet run**).
3. **Independent defect fixes (Phase 3).** Pre-fixed items left as verify-and-retire; A11 importer and a partial A14 CLI batch shipped as new code.
4. **Retention policy (cross-cutting).** Landed with Phase-2 prompt surgery as the D4 Category-C rule.

### The six decisions — how they resolved

**D1 — Should the coordinator prompt be generated from the CLI schema?**
_Decision (held):_ Not in v1; delete the obsoleted lines by fixing the surfaces first. Still `future` after the surgery.

**D2 — Is there a mechanism to propose a prompt amendment?**
_Decision (held as dependency note):_ Ride on the worker proposal API; do not build a parallel path. **Not implemented in this project.** Prompt amendments remain a file-a-chore-that-edits-`BossPaneModel.swift` loop until the proposal API accepts "coordinator prompt" as a target.

**D3 — Where does durable operational knowledge live, and who can read it?**
_Decision (held and executed):_ Repo `AGENTS.md` / `docs/` for anything a **worker** needs. Coordinator memory is invisible to workers. The original seven stranded runbooks migrated (or are mid-migration) into mono and flunge docs; **#2445** then landed three further mono-side operational notes that had still lived only in private coordinator memory (macOS bazel/Xcode pin, forensic surfaces, work-item id text-leakage rule) plus a root-`AGENTS.md` index pointing workers at them. No automated sync — the retention policy (D4) prevents divergence at the source.

**D4 — Retention/curation policy for coordinator memory going forward.**
_Decision (held and shipped into the prompt in #2439):_ **Memory is for the operator's personal working style and facts about the operator only. Anything describing Boss's or cube's behaviour is a bug report and must become a work item (or a repo doc), never a note.** T-prune is still the one-time application of that rule to the existing store.

**D5 — Correct cube lease TTL and release policy.**
_Decision as designed:_ bias toward recoverability; long wall-clock backstop rather than 30m.
_As built (diverged on value and on which const):_ Cube's `DEFAULT_LEASE_TTL_SECS` was **already 24h** (since the #2219 crash-and-restart fix). The real bug was the **engine** still owning `LEASE_TTL_SECS = 1800` and **passing it on every heartbeat**, re-clamping every live worker lease to now+30m after the first heartbeat. #2418 raised the engine constant to **86400 (24h)** to match cube; heartbeat cadence stayed **300s**. The design's proposed **4h** backstop was not used — operator direction for this change was "match cube / err toward recoverability," and real reclaim does not depend on TTL (confirm-dead auto-reap ~15 min + force-release both bypass it).

**D6 — Resolve the prompt contradictions.**

- _Take-the-conn persistence._ Ruling applied **before** this project's prompt-surgery task: take-the-conn is **per-ask, not a session mode** (shipped in #2274; reconfirmed present after #2437/#2439). The attentions-manifest yes/no was effectively answered in the negative (does not persist).
- _Investigation doc-link affordance._ Stale "exactly like a design task" claim removed in #2439; A8 already made the real affordance true.

### Acceptance criterion for the project

The project is complete when **every one of the 61 Category-A/B memory files has been retired** — either because the item that retires it has merged and the memory was deleted in the operator-approved pruning pass, or because re-verification showed the memory was already stale. **Code and surfaces for the wave are largely on main; the acceptance count is not closed until T-prune runs.** Each implementation row below still names the files it retires; T-prune remains the authoritative reconciliation against the live store (including the five post-sweep unclassified notes).
