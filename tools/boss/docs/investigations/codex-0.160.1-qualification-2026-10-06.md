# Qualifying codex-cli 0.160.1 for the codex driver

- **Date:** 2026-10-06
- **Kind:** version qualification — changelog review against the driver's measured contracts, plus a live re-measurement of the TUI surfaces the driver screen-scrapes
- **Pins:** from `codex-cli 0.153.4` to `codex-cli 0.160.1` (`tools/boss/engine/core/codex_cli_version.bzl`); pane mode `--no-alt-screen`, the spawn line `CodexDriver::build_codex_command` ships
- **Isolation:** every live run used a scratch `CODEX_HOME` under the session scratchpad seeded with a writable byte copy of `auth.json` (per [`codex-auth-isolation-2026-07-26.md`](codex-auth-isolation-2026-07-26.md)), its own tmux server (`tmux -L …`, never Boss's), and the release tarball extracted next to its `codex-code-mode-host`. The operator's `~/.codex` and installed `codex` were read, never written. Control runs used the installed 0.153.4 with the same harness.
- **Related:** [`codex-tui-liveness-marker-stability-2026-07-31.md`](codex-tui-liveness-marker-stability-2026-07-31.md) (the marker method), [`codex-tui-pivot-pricing-2026-07-30.md`](codex-tui-pivot-pricing-2026-07-30.md) (spawn-line contract), [`codex-pretooluse-decision-vocabulary-2026-07-30.md`](codex-pretooluse-decision-vocabulary-2026-07-30.md) (hook dialect)

## Why

On 2026-10-06 the operator's machine auto-updated codex from 0.153.4 to 0.160.1. 0.159 and 0.160 ship a TUI overhaul (new welcome screen, borderless header, turn footers, interruption notice), and 0.156/0.157 introduced a shared background app-server daemon that interactive sessions attach to by default. Boss pins a version only for tests; production workers run whatever `codex` is on `PATH`. The machine was rolled back and this pass qualifies 0.160.1 so the move can be deliberate.

## Changelog items reviewed (0.154 → 0.160.1)

- 0.154 `mcp-server` subcommand removed — never used.
- 0.154/0.155 Windows daemon, worktrees (`--worktree`), voice, Touch ID — not on the spawn line.
- 0.156 `/tui` fullscreen opt-in, `--no-daemon`, `/daemon`, clipboard forwarding under tmux — see daemon rows above; `--no-alt-screen` still selects inline mode.
- 0.157 fullscreen transcript by default, automatic daemon startup by default, "respected tmux mouse settings" — measured above (`--no-alt-screen` keeps inline mode; `--strict-config` keeps embedded mode; mouse stays on).
- 0.158 terminal-input approval enabled by default, native POSIX spawning for command hooks, config key alias normalisation — `-a never` unchanged; hooks still receive the payload on stdin and inherit the pane env; no driver key is aliased.
- 0.159 welcome screen / header refresh, short neutral interruption notice, turn tips, `Worked for …` footers, `tui.prompt_suggestions` removed (never written) — the `/model to change` marker loss and the notice text change above.
- 0.160 `instant_interrupt` / `daemon_auto_start` / `unified_exec_tty` feature flags (all absent from the rendered config), plan-mode hint, Option-key hint separator — no impact.
- 0.160.1 Windows remote MCP env preservation — no impact.

## Harness notes

Pane submission via `tmux send-keys -l -- <text>` followed immediately by `send-keys C-m` — the shape `boss_tmux::send_keys` uses — intermittently leaves a long prompt in the composer with a newline inserted instead of submitting, on **both** 0.153.4 and 0.160.1 (first attempt after a turn ends in 2/2 harness runs per version; a 1 s gap before `C-m` submitted reliably). The engine's pane delivery already waits for echo rather than submission, so this is a pre-existing property of the TUI's paste-burst handling, not a 0.160 change; it is recorded here and left out of this qualification.
