# Cube leases: cache affinity, recovery, and Boss simplification

- Date: 2026-10-14.
- Source revision: `4d9df110a44b802a5aa8d8a00c11e6a632721731`, current `main@origin` after `jj git fetch` during this investigation.
- Scope: investigation only; no implementation changes.
- Provenance: operator-supplied description and read-only snapshot from approximately 13:55 CDT. Production state was not accessed.

A workspace lease should buy a convenient warm workspace, not preserve a work item. Boss already recovers ordinary executions from shared jj references; its remaining lease-driven recovery and liveness decisions should be removed or separated from actual worker supervision.

## 1. Where work lives, and remaining dependencies

The recovery record contains `repo_path` and `host_id`; its names are `boss-recovery/<execution>`, `boss/<execution>`, and `boss-base/<execution>`. The recovery namespace is intentionally independent of publication refs that cube can consume after merge. `LocalJj::shared_repo` resolves the workspace's `.jj/repo` pointer to the canonical repository, and restoration operates from that shared repository into a destination workspace. [recovery/execution_bookmark.rs:90–175](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/recovery/src/execution_bookmark.rs#L90-L175) [recovery/execution_bookmark.rs:392–425](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/recovery/src/execution_bookmark.rs#L392-L425)

The baseline is created separately from the recovery/publication pointers. Workers must advance both head bookmarks before editing a new change and checkpoint edits with `jj status`; jj rewrites then move those bookmarks with the change. This preserves **snapshotted, reachable history**, not every byte in a process's memory or every unsnapshotted/ignored file. The baseline is a comparison anchor, not a lease. [recovery/execution_bookmark.rs:303–349](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/recovery/src/execution_bookmark.rs#L303-L349) [core/execution_bookmark_recovery.rs:14–39](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/execution_bookmark_recovery.rs#L14-L39)

Ordinary dispatch now explicitly sets `prefer = None`, `allow_dirty = false`, and selects `any_free`. `recover_execution_bookmark` reads the predecessor's record, then restores/rebases it into the new lease, including revision positioning on the bound PR's base. It does not inspect the old workspace or require the old lease ID. [core/coordinator/execution.rs:2082–2107](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/execution.rs#L2082-L2107) [core/coordinator/blocked_workspace.rs:21–175](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/blocked_workspace.rs#L21-L175)

There are three important qualifications:

1. **A real old-workspace dependency remains in startup pane respawn.** `resume_pane_spawn_for_running_execution` requires the recorded lease ID, workspace ID, and path, reconstructs a `CubeWorkspaceLease`, and calls `run_execution` without fresh allocation. `startup_pane_reconcile` calls it for an absent pane after checking host and durable PID. This is a startup gap-repair optimization, not evidence that jj recovery needs retention. Replace the shortcut with ordinary allocation and bookmark positioning once Boss proves the prior spawn is absent. [core/coordinator/run.rs:1108–1219](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/run.rs#L1108-L1219) [core/startup_pane_reconcile.rs:257–328](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/startup_pane_reconcile.rs#L257-L328)
2. **The shared store's host matters.** Recovery rejects `record.host_id != adapter.host_id()`; local crash backup explicitly refuses a remote recovery store. A fresh workspace on the same host works; transferring unpushed work to a different host is not implemented by this path. An unavailable host/store is a real recovery dependency, but holding its cube lease does not make the store available. [core/coordinator/blocked_workspace.rs:41–47](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/blocked_workspace.rs#L41-L47) [core/execution_bookmark_recovery.rs:43–54](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/execution_bookmark_recovery.rs#L43-L54)
3. **Some durable fields and comments still describe obsolete recovery.** Transient recovery populates `preferred_workspace_id` and `allow_dirty`, and its tests assert them, while allocation ignores them. These are stale policy remnants to remove, not an active requirement to retain that workspace. [core/work/executions_runs.rs:490–523](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/work/executions_runs.rs#L490-L523) [core/transient_recovery.rs:1137–1180](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/transient_recovery.rs#L1137-L1180) [core/coordinator/execution.rs:2090–2094](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/execution.rs#L2090-L2094)

The known baseline-after-rebase, diverged-pointer, and missing-baseline wedges are reference-integrity issues. Head selection resolves the baseline and compares ancestry; divergent histories fail rather than silently discard one. None of these checks consults a cube lease, so retention cannot fix them. Their repair remains separate work. [recovery/execution_bookmark.rs:232–299](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/recovery/src/execution_bookmark.rs#L232-L299)

**Conclusion:** preserve jj references and shared-store access; remove recovery policy based on keeping a particular cube workspace. Keep actual driver teardown before disposing of a directory because it can read driver state there; that is runtime cleanup, not source-history preservation. [core/completion/teardown.rs:20–32](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/completion/teardown.rs#L20-L32)

## 2. What moving workspaces costs

Cube's pool uses `jj workspace add` against a canonical repository, not a separate clone per worker. Boss's recovery path then positions the fresh workspace from references as described above. [cube/app/reset.rs:248–257](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/reset.rs#L248-L257) [core/coordinator/blocked_workspace.rs:7–20](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/blocked_workspace.rs#L7-L20)

Bazel's output-base path is derived from the workspace path. Reusing that path can retain server/action state and build outputs; changing it can require another output base and analysis/build setup. This is the concrete cache-affinity benefit. It does **not** imply that every lease is prebuilt, or that moving discards shared disk/remote action-cache hits. [cube/app/bazel_output_base.rs:1–29](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/bazel_output_base.rs#L1-L29) [cube/app/bazel_output_base.rs:79–87](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/bazel_output_base.rs#L79-L87) [tools/boss/engine/driver/src/codex.rs:872–884](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/driver/src/codex.rs#L872-L884)

Inference: ordinary same-host movement costs checkout/setup and potentially a cold per-workspace Bazel base, not loss of bookmarked code. It can also require rerunning validation, which recovery instructions explicitly require. Cross-host migration adds the store-access limitation above. [core/execution_bookmark_recovery.rs:30–39](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/execution_bookmark_recovery.rs#L30-L39)

## 3. Expiry, active work, and Boss exclusivity

### Initial TTL and what actually expires

Boss does **not pass an explicit TTL on initial allocation**: its lease argv contains task/setup-failure/exclusion options. Cube itself sets `lease_expires_at = leased_at + DEFAULT_LEASE_TTL_SECS`, and that default is 86,400 seconds. The periodic worker heartbeat explicitly requests 86,400 seconds; the older per-run `HeartbeatGuard` passes `None` and inherits cube's default. [core/cube_commands.rs:227–259](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_commands.rs#L227-L259) [cube/app/workspace.rs:52–74](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/workspace.rs#L52-L74) [cube/app/workspace.rs:290–292](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/workspace.rs#L290-L292) [core/cube_lease_heartbeat.rs:368–378](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_lease_heartbeat.rs#L368-L378) [core/cube_lease_heartbeat.rs:1019–1020](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_lease_heartbeat.rs#L1019-L1020) [core/coordinator.rs:454–464](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator.rs#L454-L464)

Expiry is lazy. A subsequent lease call sweeps expired rows under the repo lock; `expire_stale_leases` clears lease ownership and marks the workspace free. This neither terminates nor fences the previous process. A heartbeat simply advances expiry for the still-recorded lease ID. [cube/app/workspace.rs:240–260](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/workspace.rs#L240-L260) [cube/store.rs:1100–1156](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/store.rs#L1100-L1156) [cube/app/workspace.rs:1484–1490](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/workspace.rs#L1484-L1490)

On reuse, cube health/reset guards can reject dirty work and quarantine the old workspace, allocating a fresh one instead. If reuse passes, reset runs `jj new <main>@<remote>` before Boss receives the lease. No worker-process check accompanies that reset. [cube/app/workspace.rs:1090–1150](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/workspace.rs#L1090-L1150) [cube/app/reset.rs:52–99](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/reset.rs#L52-L99) [cube/app/reset.rs:205–244](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/cube/src/app/reset.rs#L205-L244)

Inference: an existing bookmarked snapshot stays in the shared store when the workspace's `@` moves. But a still-running agent can continue writing after reset, overwrite another writer's files, or checkpoint onto the wrong change. Dirty guards reduce exposure; they are not a transaction covering future writes. Therefore “resumable” is sound for preserved snapshots; “only a slowdown” is not a complete guarantee for concurrent live editing. The worker checkpoint contract and the post-allocation occupancy guard explicitly recognize this boundary. [core/execution_bookmark_recovery.rs:18](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/execution_bookmark_recovery.rs#L18) [core/coordinator/execution.rs:1296–1307](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/coordinator/execution.rs#L1296-L1307)

**Boss defect to brief:** establish durable host-qualified workspace ownership for preparing, spawning, live, stopping, and uncertain runs, independent of cube expiry and execution terminal status. Feed all occupied IDs to cube exclusions **before** allocation, serialize Boss allocation/ownership registration, and revalidate before spawn. Do not run a resetting release on a rejected occupied workspace. Recover the ownership inventory before restarting dispatch, including remote and mid-spawn workers.

This is a proposed Boss fix, not a recommendation to make cube a liveness oracle. Boss cannot fence arbitrary external tools that ignore its ownership inventory; that is outside the claimed guarantee for two Boss agents. A lease heartbeat remains useful to avoid churn, but is not proof of exclusivity.

### The 24-hour assertion cannot be established from the supplied rows

A dispatched pane parks the execution in `waiting_human` until a later Stop; execution lifetime therefore includes idle/waiting/hung periods. Remote `work_runs` can even be marked completed milliseconds after successful spawn while the worker remains active. Waiting-review/merge states are explicitly treated as cases where the worker exited by design. [core/lost_workspace_sweep.rs:27–41](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/lost_workspace_sweep.rs#L27-L41) [core/remote_lease_reconcile.rs:35–42](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/remote_lease_reconcile.rs#L35-L42) [core/cube_lease_heartbeat.rs:554–565](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_lease_heartbeat.rs#L554-L565)

There is also an explicitly unbounded escalation-pending hold, and stale-worker logic distinguishes actual tool activity, idle state, missing evidence, and operator holds rather than imposing a blanket wall-clock kill. Thus the code permits long-lived workers and does not establish “nothing works beyond 24 hours.” [core/completion.rs:2185–2199](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/completion.rs#L2185-L2199) [core/stale_worker_sweep.rs:38–108](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/stale_worker_sweep.rs#L38-L108)

**Inference and limit:** the long cancelled reviews are consistent with idle or stranded rows, but the aggregates cannot prove that interpretation for any particular execution, including the completed 37.1-hour review. Resolving their histories would require per-run driver progress, process, and terminal-event timelines; no production query is proposed here.

**Recommendation:** retain at most one best-effort heartbeat service, targeted by Boss's actual live-owner inventory (including remote owners if supported), as a performance optimization for long-running work. Do not assert a local-only service protects remote affinity. It is not required for source preservation or the proposed Boss occupancy invariant. Delete DB-state fallback, terminal-row refresh, and duplicate per-run/ladder heartbeat policy. Twenty-four hours reduces accidental reuse frequency; it does not establish a lifetime bound. The server's “~30 min” comment is stale against both current constants and should be corrected as part of that simplification. [core/app/server.rs:1700–1716](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/app/server.rs#L1700-L1716)

## 4. Why the disabled remote host is still contacted

The operator reports six July/August orphaned executions on disabled, unresolvable `anaplian`, auto-disabled after 1,559 failures, and repeated heartbeat warnings roughly every 5.5 minutes. This is supplied incident evidence, not independently queried state.

The current code explains a self-sustaining target:

1. `terminal_remote_cleanup_runs` includes terminal rows with a recorded remote PID and cube lease (or active persona), excludes tmux-owned executions, and has no host-enabled predicate. [core/work/run_rows.rs:1196–1228](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/work/run_rows.rs#L1196-L1228)
2. The terminal heartbeat loop selects recorded PIDs, calls `heartbeat_one`, and increments failure counts. Unlike the other two populations, it never calls `record_heartbeat_result`. The three-failure auto-reap/offline-host shortcut therefore does not retire this population. [core/cube_lease_heartbeat.rs:895–937](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_lease_heartbeat.rs#L895-L937) [core/cube_lease_heartbeat.rs:1113–1129](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_lease_heartbeat.rs#L1113-L1129) [core/cube_lease_heartbeat.rs:1170–1185](https://github.com/spinyfin/mono/blob/4d9df110a44b802a5aa8d8a00c11e6a632721731/tools/boss/engine/core/src/cube_lease_heartbeat.rs#L1170-L1185)

## 6. Proposed end state

1. **Before allocation:** Boss reconciles and reserves ownership, supplies occupied workspace exclusions, and serializes its allocation/registration window. PR/chain guards remain an additional constraint.
2. **At dispatch:** lease clean scratch, restore shared-store references, provision driver state, and spawn. Preserve `boss-recovery/`, publication, and baseline handling.
3. **During work:** optionally refresh only actual live-owner cache handles through one bounded best-effort service. Failed renewal never kills a worker, changes task status, or creates an unbounded retry obligation.
4. **At termination:** stop/fence the process and preserve uncertain ownership if stopping is unconfirmed. Finish driver teardown before any directory-resetting release; if process exit remains unconfirmed, do not reset its directory (omit cache release and let TTL expire, or use a non-resetting handback). Attempt eligible cache release once asynchronously with a bound covering adapter resolution and cube; clear the actionable handle regardless of cleanup success.
5. **Afterward:** no waiting-review/merge affinity retention, no terminal heartbeat, no lease-only reconciler/breaker/startup drain. Cube's next allocation lazily expires missed releases.
6. **Recovery:** allocate elsewhere on the same shared store. Replace the old-lease startup respawn shortcut. A dead/unavailable store or invalid reference remains an explicit recovery error, not a lease-lifetime policy.

This replaces the multiple heartbeat populations, per-run guard, ladder upkeep, lease-derived startup verdicts, terminal release retry loop, and stale recovery preference policy identified above. It deliberately retains worker supervision, ownership, driver cleanup, and source recovery.

The choice is **one optional live-owner affinity heartbeat**, not zero based on an unproved 24-hour bound, and not a local-only policy silently excluding remote work. Its only purpose is avoiding expensive workspace churn. Fixing Boss ownership is the correctness work and must precede removal of protections currently standing in for it.

## Open questions and explicit non-goals

- The individual >24-hour executions cannot be classified as continuously active, idle, or hung from aggregate timestamps. This limits the verdict; it does not block the documented removal plan.
- Cross-host transfer of unpushed shared-store work is a separate capability. Lease retention cannot substitute for it.
- The known reference-integrity wedges and app read-RPC admission timeouts remain separate investigations.
- The chosen end state keeps only an optional live-owner affinity refresh because there is no proved universal 24-hour work bound. No indefinite terminal retention, lease-derived execution death, or mandatory cache-release retry is justified.
